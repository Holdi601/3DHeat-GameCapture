# Ажурирања {#updates}

3DHeat GameCapture проверава GitHub издања овог репозиторијума при покретању, јавља кад је нова верзија изашла и нуди ажурирање. Код: [`heat3d_update/`](https://github.com/Holdi601/3DHeat-GameCapture/tree/main/heat3d_update).

## Када се провера покреће {#when-the-check-runs}

- `python -m heat3d_capture <глагол>` - пре него што се команда покрене.
- `python -m heat3d_capture.ui` (и `scan.bat`) - пре него што се прозор отвори.
- `python -m heat3d_update` - на захтев, увек поново питајући GitHub.

## Како провера ради {#how-the-check-works}

- Инсталирана верзија је фајл `VERSION` у корену репозиторијума (на пример `1.0.1`).
- Најновије издање се тражи са `https://api.github.com/repos/Holdi601/3DHeat-GameCapture/releases/latest`, с временским ограничењем од **5 секунди**. Спора мрежа никад не заустави алат дуже.
- Одговор се чува у кешу **6 сати** у `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-GameCapture.json` (`~/.cache/3DHeat/...` без `LOCALAPPDATA`). Сваки 3DHeat алат има свој фајл кеша. „Још нема издања" (HTTP 404) се кешира као одговор; остали неуспеси се не кеширају и значе само да нема обавештења.
- Верзије се упоређују бројчано (`v1.2.3` или `1.2.3`; све после `-` или `+` се занемарује).
- Ван мреже, са ограничењем броја захтева или иза проксија, алат наставља с верзијом коју има.

## Шта се дешава кад је новије издање изашло {#what-happens-when-a-newer-release-is-out}

При покретању исписује у ток грешака:

```text
[heat3d_capture] 3DHeat GameCapture 1.1.0 is out (this is 1.0.1). https://github.com/...
```

- Кад има терминал за одговор, пита `Update now? [Y/n]` (Enter, `y`, `yes`, `j`, `ja` значе да). После успешног ажурирања **иста команда се поново покреће**, на новом коду.
- Без терминала (цев, заказано покретање) исписује `Run python -m heat3d_update in <folder> to update.` и наставља непромењено.

## Како се ажурирање примењује {#how-an-update-is-applied}

Зависи од тога како су алати инсталирани:

- **git клон** (фасцикла `.git` и `git` у PATH-у): `git pull --ff-only`. Одбија се док checkout има локалне измене у праћеним фајловима - то је туђи рад; прво их комитујте или одложите (stash).
- **Преузета копија**: изворна архива издања се преузима, распакује у привремену фасциклу (уноси ван сопствене фасцикле архиве се прескачу), и **проверава се да је верзија коју тврди** у свом `VERSION` фајлу. Затим се њени фајлови копирају преко ове фасцикле. Унутар Python пакета самог издања (фасцикле `heat3d_*` на врху репозиторијума, и један ниво испод за стари monorepo распоред), `.py` модули које издање више нема се бришу, па застарели модул не може да заклони своју замену.

Ваши фајлови - снимци, датотеке кругова, подешавања, извози, `.venv` - никад се не дирају: записују се само фајлови који су део издања.

## Ручно {#by-hand}

```bash
python -m heat3d_update            # check and update
python -m heat3d_update --check    # only say whether a newer release is out
```

Исписује `Up to date: <version>.`, `No release found ... offline, or nothing published yet.`, или нову верзију и шта је урадио. Излазни код 1 ако ажурирање није могло да се примени.

## Искључивање {#switching-it-off}

Поставите **`HEAT3D_NO_UPDATE=1`** (било која вредност осим празне, `0`, `false`, `no`). То искључује проверу и обавештење при покретању. Сам `python -m heat3d_update` и даље проверава кад се покреће ручно.
