# Ажурирања {#updates}

3DHeat GameCapture ги проверува GitHub изданијата на ова складиште кога стартува, кажува
кога е објавена понова верзија и нуди да се ажурира. Код:
[`heat3d_update/`](https://github.com/Holdi601/3DHeat-GameCapture/tree/main/heat3d_update).

## Кога се врши проверката {#when-the-check-runs}

- `python -m heat3d_capture <verb>` - пред да се изврши командата.
- `python -m heat3d_capture.ui` (и `scan.bat`) - пред да се отвори прозорецот.
- `python -m heat3d_update` - на барање, секогаш прашувајќи го GitHub одново.

## Како работи проверката {#how-the-check-works}

- Инсталираната верзија е датотеката `VERSION` во коренот на складиштето (на пример `1.0.1`).
- Најновото издание се бара од `https://api.github.com/repos/Holdi601/3DHeat-GameCapture/releases/latest`,
  со ограничување од **5 секунди**. Бавна мрежа никогаш не ја застојува алатката подолго.
- Одговорот се чува во кеш **6 часа** во
  `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-GameCapture.json` (`~/.cache/3DHeat/...` без
  `LOCALAPPDATA`). Секоја алатка на 3DHeat има своја датотека за кеш. „Сè уште нема издание“
  (HTTP 404) се кешира како одговор; другите неуспеси не се кешираат и едноставно значат дека
  нема известување.
- Верзиите се споредуваат бројчано (`v1.2.3` или `1.2.3`; сè по `-` или `+` се игнорира).
- Офлајн, со ограничена стапка или зад прокси, алатката продолжува со верзијата што ја има.

## Што се случува кога има понова верзија {#what-happens-when-a-newer-release-is-out}

При стартување печати, на излезот за грешки:

```text
[heat3d_capture] 3DHeat GameCapture 1.1.0 is out (this is 1.0.1). https://github.com/...
```

- Ако има терминал на кој може да се одговори, прашува `Update now? [Y/n]` (Enter, `y`, `yes`,
  `j`, `ja` значат да). По успешно ажурирање **истата команда се стартува повторно**, на новиот
  код.
- Без терминал (цевка, закажано извршување), печати
  `Run python -m heat3d_update in <folder> to update.` и продолжува непроменето.

## Како се применува ажурирањето {#how-an-update-is-applied}

Зависи од тоа како се инсталирани алатките:

- **git клон** (папка `.git` и `git` во PATH): `git pull --ff-only`. Се одбива додека
  работната копија има локални промени на следени датотеки - тоа е нечија работа; прво
  направете им commit или stash.
- **Преземена копија**: изворната архива на изданието се презема, се распакува во привремена
  папка (записите надвор од сопствената папка на архивата се прескокнуваат) и **се проверува
  дали е верзијата што тврди дека е** според нејзината датотека `VERSION`. Потоа нејзините
  датотеки се копираат врз оваа папка. Во сопствените Python-пакети на изданието (папките
  `heat3d_*` на врвот на складиштето, и едно ниво подлабоко за старата монорепо-структура),
  модулите `.py` што изданието повеќе ги нема се бришат, за застарен модул да не го засени
  својот заменик.

Вашите сопствени датотеки - снимки, датотеки на кругови, поставки, извози, `.venv` - никогаш не
се допираат: се пишуваат само датотеките што се дел од изданието.

## Рачно {#by-hand}

```bash
python -m heat3d_update            # check and update
python -m heat3d_update --check    # only say whether a newer release is out
```

Печати `Up to date: <version>.`, `No release found ... offline, or nothing published yet.`, или
новата верзија и што направил. Излезен код 1 ако ажурирањето не можело да се примени.

## Исклучување {#switching-it-off}

Поставете **`HEAT3D_NO_UPDATE=1`** (секоја вредност освен празна, `0`, `false`, `no`). Тоа ги
исклучува проверката и известувањето при стартување. `python -m heat3d_update` сам по себе
сепак проверува кога се извршува рачно.
