# Референца на командите {#command-reference}

Сите команди се пуштаат од папката на складиштето, со околината на проектот:

```bash
.venv\Scripts\python -m heat3d_capture <verb> [options]
```

| Команда | Што прави |
|---|---|
| [`route`](#route) | Ги снима само позициите на еден круг на Forza, за наоѓање на мапата во датотеките на играта |
| [`telemetry`](#telemetry) | Го снима секој канал, по една датотека за круг, за табот Анализа на трка |
| [`laps`](#laps) | Чита библиотека со кругови на FH Companion и ги пишува рутата и мерењата на една патека |
| [`reconstruct`](#reconstruct) | Решава снимка офлајн и пишува `.glb` |
| [`hud`](#hud) | Ги чита сопствените дејства, смрти и трага на минимапата на играчот, како и kill feed, од снимка |
| [`locate`](#locate) | Каде е земена секоја слика од снимката, спрема рендери на нивото |
| [`python -m heat3d_capture.ui`](#the-scan-window) | Прозорецот за скенирање |
| [`python -m heat3d_update`](#updates) | Проверува и применува ажурирање |
| [`python tools/export_onnx.py`](#the-model-converter) | Го претвора моделот за длабочина во ONNX |

Кога се стартува како `python -m heat3d_capture`, алатката најпрво проверува за понова верзија (видете
[Ажурирања](updates.md); `HEAT3D_NO_UPDATE=1` го исклучува тоа). `--help` по секоја команда ги наведува нејзините опции:

![heat3d_capture --help](../assets/img/cli-help.svg)

Код: [`heat3d_capture/__main__.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/__main__.py).

## route {#route}

```bash
python -m heat3d_capture route -o lap [--port 5300] [--seconds 0]
```

Слуша за Forza Data Out и ги чува само позициите на автомобилот, ништо друго: без модел за длабочина, без
GPU, без снимање на екранот. Код: [`telemetry/record.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/telemetry/record.py).

| Опција | По основно | Значење |
|---|---|---|
| `-o`, `--out` | задолжително | Излезна патека; нејзината наставка се заменува, па `-o lap` пишува `lap.npz` и `lap.json`. |
| `--port` | `5300` | Портот на кој праќа играта (врзана на 127.0.0.1). |
| `--seconds` | `0` | Запира по толку секунди; `0` работи до Ctrl+C. |

Позицијата се чува само додека играта известува за трка (`isRaceOn`), автомобилот се движи побрзо од
0,5 m/s и е најмалку 0,5 m од последната зачувана позиција - инаку седењето во мени со
60 пакети во секунда би ја наполнило датотеката со стартната линија. Времето на секој примерок е
времето на трката од играта, или часовникот на компјутерот кога тоа е 0. Распоредот се препознава исто како за
`telemetry` (автомобилот прво мора да се придвижи; видете [Forza](telemetry-forza.md)).

Еднаш во секунда печати примени пакети, зачувани позиции и тековната позиција, или
`nothing on port 5300 yet - is Data Out on?`. Рутата **се зачувува додека се вози**: на секои
2 секунди откако ќе пристигне нова позиција (паузата расте до дваесет пати колку траело последното зачувување,
па многу долга сесија никогаш не троши повеќе од дваесеттина од своето време на пишување), и уште
еднаш кога снимачот ќе запре од каква било причина - Ctrl+C, `--seconds` или исклучок. Секое зачувување
пишува `lap.npz.partial` / `lap.json.partial` и потоа го преместува врз вистинската датотека, па
датотеките на дискот се секогаш цели; паѓање или прекинат процес губи најмногу последните неколку
секунди. Ако ништо не е зачувано, печати како да се вклучи Data Out и излегува со код 1.

Излез:

- `lap.npz` - NumPy низи `positions` (n x 3, метри), `times`, `speeds` (m/s);
- `lap.json` - читливо без овој проект:

```json
{
  "layout": "Horizon dash",
  "samples": 4210,
  "seconds": 182.4,
  "metres_driven": 5120.7,
  "bounds": {"min": [-1200.0, 110.2, 300.5], "max": [-400.3, 160.8, 1400.0]},
  "positions": [[-1180.2, 112.0, 310.4], ...]
}
```

Позициите се сопствените светски координати на играта, што ги прави рачка за
наоѓање на истата земја во датотеките на играта: командата `course` на
[3DHeat GameFiles](https://github.com/Holdi601/3DHeat-GameFiles) го зема овој
JSON и ја извезува патеката преку која трчал кругот.

## laps {#laps}

```bash
python -m heat3d_capture laps                                   # list the courses
python -m heat3d_capture laps "a racing circuit" -o races/circuit [--library DIR] [--margin 80]
```

Ја чита библиотеката со кругови што ја чува FH Companion и пишува две датотеки за една патека: рута што
кажува кое парче од мапата да се исече од архивата на играта, и табела со секој примерок од секој
круг. Се пишуваат заедно за да не излезат од чекор. Код:
[`telemetry/fhcompanion.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/telemetry/fhcompanion.py).

| Опција | По основно | Значење |
|---|---|---|
| `course` | нема | Име на патеката, совпаѓа слободно. Испуштете за да се листа библиотеката. |
| `-o`, `--out` | името на патеката, мали букви, празнините како `_` | Излезна патека; `.json` и `.csv` се пишуваат една до друга. |
| `--library` | `%LOCALAPPDATA%\FHCompanion\laps` | Каде се папките на патеките. |
| `--margin` | `80` | Метри додадени околу опсегот на патеката во x и z во `bounds` на рутата. |

### Листање {#listing}

Без патека го печати бројот на папки со патеки и, за секоја, бројот на датотеки со кругови
(`*.json` каде било под неа освен `course.json`) и името на патеката, потоа
`Name one to write it out:  -o <file> <course>`.

### Наоѓање патека {#finding-a-course}

Папките на патеките се именувани `<name> (course_<x>_<z>_to_<x>_<z>)` - старт и финиш,
заокружени. Патеката се наоѓа по ред: точното име на папката; делот со име од името на
папката, без разлика на големината на буквите; единствена папка чие име го содржи текстот. Повеќе совпаѓања е
грешка што ги наведува.

### Читање {#reading-it}

- `course.json` во папката, кога е читлив, ги дава името и незаокружените старт и
  финиш (`Name`, `StartX`, `StartZ`, `FinishX`, `FinishZ`); инаку тие доаѓаат од
  името на папката. Патеката се пријавува како кружна кога стартот и финишот се на помалку од 10 m
  растојание.
- Секој друг `*.json` под папката е круг (круговите стојат неколку папки длабоко - по класа,
  автомобил, поставка, ознака - а пребарувањето е едноставно рекурзивно). Датотеките се читаат како UTF-8 со ознака
  за редослед на бајти. Нечитлив круг се прескокнува. Круговите се редат по времето на снимање.
- За секој круг: `Lap.samples` (секој со `X`, `Y`, `Z`, `Speed`, `Throttle`, `Brake`, `Steer`,
  `LatG`, `LongG`, `Gear`, `Clutch`, `HandBrake`, `Puddle`, `Metres`, `Seconds`), како и класата на
  автомобилот, ординалот, индексот на перформанси, секундите на кругот, должината, времето на снимање и стоечки старт.

Печати резиме (кругови, примероци, најдобар круг и неговата класа, опсегот x/y/z).

### Излез {#output}

**`<out>.json`** - истата форма на рута што ја пишува `route`, па екстракторот на мапи прима која било:
`layout: "fhcompanion"`, `course`, `laps`, `samples`, `bounds` (проширено со `--margin` во x и
z) и `positions` на **најбрзиот** круг (една линија наместо размачкана низа од секој круг).

**`<out>.csv`** - секој примерок од секој круг, по еден ред:

| Колона | Значење |
|---|---|
| `course` | име на патеката |
| `lap` | ознака за круг: датум и време на снимање до минута, и времето на кругот |
| `car` | ординал на автомобилот |
| `car_class` | буква на класата на перформанси |
| `pi` | индекс на перформанси |
| `lap_seconds` | времето на кругот |
| `speed_kmh` | брзина во km/h |
| `x`, `y`, `z` | светска позиција, метри, 3 децимали |
| `speed_ms` | брзина, m/s |
| `throttle`, `brake`, `steer`, `lat_g`, `long_g`, `gear`, `clutch`, `handbrake`, `puddle` | како што ги снима FH Companion |
| `metres` | растојание по кругот, 3 децимали |
| `elapsed` | секунди од сопствениот почеток на кругот, 3 децимали |

Вредностите што не се позиции се пишуваат со 4 значајни цифри; позициите добиваат фиксни децимали бидејќи
4 значајни цифри би ја закачиле патеката на мрежа од еден метар. Имињата на колоните се избрани
така што прегледувачот ја мапира датотеката без да му се каже: `lap` станува сесија (два круга на еден автомобил
никогаш не се спојуваат), `car` е нешто што се движи, `car_class` е групата по која се боиме, `elapsed`
е временската оска (секој круг се порамнува на својот почеток).

На крај печати совет за сечење на мапата од играта со GameFiles, со датотеката на рутата
или со експлицитна кутија.

## reconstruct {#reconstruct}

```bash
python -m heat3d_capture reconstruct lap.mp4 -o lap.glb [--solve-budget 260] [--fuse-interval 0.4] [--model vggt-1b]
```

Реконструира снимка офлајн, со патеката на камерата решена наеднаш со VGGT. Бавно:
минути по прозорец на десктоп GPU. Му требаат PyTorch, Hugging Face `transformers` и пакетот
`vggt`, што скенерот не ги бара: наведени се во `requirements-offline.txt`, а
командата ги проверува откако ќе ја испечати линијата за лиценца и нуди да инсталира што
недостасува (излезен код 1 ако се одбие). Целосен опис:
[Офлајн реконструкција](reconstruction-offline.md).

| Опција | По основно | Значење |
|---|---|---|
| `video` | задолжително | Снимката. Излезен код 2 ако не постои. |
| `-o`, `--out` | задолжително | `.glb` што се пишува. |
| `--solve-budget` | `260` | Најмногу слики дадени на решавачот. Се распоредени по тоа колку се движи сликата, не по часовник. Повеќе е поточно и многу побавно. Повеќе од 400 планирани слики се одбива. |
| `--fuse-interval` | `0.4` | Секунди меѓу сликите споени во геометрија. |
| `--model` | `vggt-1b` | Со кои VGGT тежини да се решава: `vggt-1b` (`facebook/VGGT-1B`, некомерцијално) или `vggt-1b-commercial` (`facebook/VGGT-1B-Commercial`, со ограничен пристап; Meta мора да дозволи пристап). Линијата за лиценца што се печати прва е на тој модел. |

Најпрво ја печати линијата за лиценца на моделот, потоа секоја фаза (`masking`, `planning`, `solving`,
`fusing`, `exporting`) со поминати секунди и напредок, и на крај резиме: решени
камери, грешка на затворање, најлош шев, белешки и пишаната датотека. Излезниот код е 0 само ако е
пишана датотека.

## hud {#hud}

```bash
python -m heat3d_capture hud "<recording>.mp4" --game bf6 --player <name> -o out/match [--fps 5] [--start S] [--seconds S] [--metres-per-pixel M] [--cpu]
```

Го чита HUD-от на играта од сопствената снимка на играчот, по натпреварот: сопствените
дејства на играчот од скокачкиот прозорец со поени, смртите и оживувањата од екраните за паѓање и распоредување, трагата
на минимапата и kill feed. Пишува `<out>.parquet` (трага и настани, табела на 3DHeat),
`<out>.events.jsonl`, `<out>.summary.json` и `<out>.map.png` + `.map.json` (мозаикот на минимапата
и неговите сидришта за Map image на прегледувачот). Battlefield 6 (`bf6`) е засега единствениот профил.

Му требаат **ffmpeg и ffprobe** во PATH (`winget install Gyan.FFmpeg`, потоа нов терминал).

| Опција | По основно | Значење |
|---|---|---|
| `video` | задолжително | Снимката. |
| `-o`, `--out` | името на видеото | Излезна патека без наставка. |
| `--game` | `bf6` | Чиј HUD да се чита. |
| `--player` | погодено | Името на играчот како што го покажува kill feed, совпаѓа слободно. |
| `--fps` | `5` | Примероци од минимапата во секунда. |
| `--start`, `--seconds` | цело видео | Дел од снимката што се чита. |
| `--metres-per-pixel` | нема | Размерот на минимапата, кога е познат; без него позициите се во пиксели на минимапата. |
| `--cpu` | исклучено | Декодира на процесорот дури и кога има NVIDIA картичка. |

Целосен опис: [Читање на HUD од снимка](hud-video.md).

## locate {#locate}

```bash
python -m heat3d_capture locate build level.glb -o level.db [--game bf6] [--spacing 2.5] [--shadows]
python -m heat3d_capture locate frames recording.mp4 --db level.db -o out/match [--fps 2] [--minimap match.parquet]
python -m heat3d_capture locate eval out/match.parquet --truth poses.parquet [--offset S] [--unit-metres 1]
python -m heat3d_capture locate train level.glb -o level.head.pt [--places auto] [--real out/match.parquet recording.mp4]
python -m heat3d_capture locate refmap level.glb deploy.png -o out/refmap [--mpp 0.5]
python -m heat3d_capture locate minimap recording.mp4 --refmap out/refmap -o out/minimap.parquet [--hud out/match.parquet]
```

`build` рендерира ниво од секое место каде што може да стои играч и ги индексира рендерите; `frames`
ја сместува секоја земена слика од снимката спрема него, од самата слика, со трагата од минимапата на командата `hud`
како резерва; `eval` го споредува резултатот со познати позиции на камерата; `train` тренира
модел на места за секоја мапа на рендери на нивото (и на слики што еден пуштање веќе ги лоцирало), за `build --head`;
`refmap` ја става сопствената мапа на играта (нејзиниот екран за распоредување) на нивото, а `minimap` ја чита
минимапата од снимката спрема неа, слика по слика - претходник што `frames --minimap` може да го земе. Му требаат PyTorch
и `requirements-locate.txt`. **Експериментално:** на вистински снимки досега сместува само мал дел од
сликите. Секоја опција, излезите и методот:
[Лоцирање слики во ниво](locate.md); целосната листа на опции: [Референца на командите](../cli-reference.md).

## Конверторот на моделот {#the-model-converter}

```bash
python tools/export_onnx.py [--size small|base|large] [--out PATH] [--side 518] [--opset 17]
```

Контролна точка на Depth Anything V2 ја претвора во ONNX датотеката што ја пушта скенерот. Му требаат PyTorch,
`transformers` и `onnxscript`. Видете [Длабочина](reconstruction-depth.md#building-the-model).
