# Αναφορά εντολών {#command-reference}

Όλες οι εντολές εκτελούνται από τον φάκελο του αποθετηρίου, με το περιβάλλον του έργου:

```bash
.venv\Scripts\python -m heat3d_capture <verb> [options]
```

| Εντολή | Τι κάνει |
|---|---|
| [`route`](#route) | Καταγράφει μόνο τις θέσεις ενός γύρου του Forza, για να βρεθεί ο χάρτης στα αρχεία του παιχνιδιού |
| [`telemetry`](#telemetry) | Καταγράφει κάθε κανάλι, ένα αρχείο γύρου για κάθε γύρο, για την καρτέλα Ανάλυση αγώνα |
| [`laps`](#laps) | Διαβάζει τη βιβλιοθήκη γύρων του FH Companion και γράφει τη διαδρομή και τα δείγματα μιας πίστας |
| [`reconstruct`](#reconstruct) | Λύνει μια εγγραφή εκτός σύνδεσης και γράφει ένα `.glb` |
| [`hud`](#hud) | Διαβάζει τις ενέργειες του παίκτη, τους θανάτους και τη διαδρομή του στον χάρτη, καθώς και τη ροή των φόνων, από μια εγγραφή |
| [`locate`](#locate) | Πού λήφθηκε κάθε καρέ μιας εγγραφής, σε σύγκριση με αποδόσεις της πίστας |
| [`python -m heat3d_capture.ui`](#the-scan-window) | Το παράθυρο σάρωσης |
| [`python -m heat3d_update`](#updates) | Ελέγχει και εφαρμόζει μια ενημέρωση |
| [`python tools/export_onnx.py`](#the-model-converter) | Μετατρέπει το μοντέλο βάθους σε ONNX |

Όταν ξεκινά ως `python -m heat3d_capture`, το εργαλείο ελέγχει πρώτα αν υπάρχει νεότερη έκδοση (βλ.
[Ενημερώσεις](updates.md)· το `HEAT3D_NO_UPDATE=1` το απενεργοποιεί). Το `--help` μετά από οποιαδήποτε
εντολή εμφανίζει τις επιλογές της:

![Η βοήθεια του heat3d_capture --help](../assets/img/cli-help.svg)

Κώδικας: [`heat3d_capture/__main__.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/__main__.py).

## route {#route}

```bash
python -m heat3d_capture route -o lap [--port 5300] [--seconds 0]
```

Ακούει για το Forza Data Out και κρατά μόνο τις θέσεις του αυτοκινήτου, τίποτε άλλο: χωρίς μοντέλο βάθους,
χωρίς GPU, χωρίς λήψη εικόνας. Κώδικας: [`telemetry/record.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/telemetry/record.py).

| Επιλογή | Προεπιλογή | Σημασία |
|---|---|---|
| `-o`, `--out` | απαιτείται | Διαδρομή εξόδου· το επίθημά της αντικαθίσταται, οπότε το `-o lap` γράφει `lap.npz` και `lap.json`. |
| `--port` | `5300` | Η θύρα στην οποία στέλνει το παιχνίδι (δεσμευμένη στο 127.0.0.1). |
| `--seconds` | `0` | Σταματά μετά από τόσα δευτερόλεπτα· το `0` τρέχει μέχρι να πατήσετε Ctrl+C. |

Μια θέση κρατιέται μόνο όταν το παιχνίδι αναφέρει ότι τρέχει αγώνας (`isRaceOn`), το αυτοκίνητο κινείται
ταχύτερα από 0,5 m/s, και απέχει τουλάχιστον 0,5 m από την τελευταία κρατημένη θέση. Αλλιώς, ένας παίκτης
που στέκεται σε ένα μενού θα γέμιζε το αρχείο με τη γραμμή εκκίνησης, με 60 πακέτα το δευτερόλεπτο. Ο χρόνος
κάθε δείγματος είναι ο χρόνος αγώνα του παιχνιδιού, ή το ρολόι του υπολογιστή όταν εκείνος είναι 0. Η
διάταξη ανιχνεύεται ακριβώς όπως στο `telemetry` (το αυτοκίνητο πρέπει πρώτα να κινηθεί· βλ. [Forza](telemetry-forza.md)).

Κάθε δευτερόλεπτο τυπώνει τα πακέτα που ελήφθησαν, τις θέσεις που κρατήθηκαν και την τρέχουσα θέση, ή
`nothing on port 5300 yet - is Data Out on?`. Η διαδρομή **αποθηκεύεται ενώ οδηγείτε**: κάθε 2 δευτερόλεπτα,
μόλις έχει φτάσει νέα θέση (το διάστημα μεγαλώνει ως είκοσι φορές τη διάρκεια της προηγούμενης αποθήκευσης,
ώστε μια πολύ μεγάλη συνεδρία να μη δαπανά ποτέ περισσότερο από το ένα εικοστό του χρόνου της στην εγγραφή),
και άλλη μία φορά όταν σταματά η καταγραφή για οποιονδήποτε λόγο: Ctrl+C, `--seconds` ή εξαίρεση. Κάθε
αποθήκευση γράφει πρώτα τα `lap.npz.partial` / `lap.json.partial` και μετά τα μεταφέρει πάνω από τα κανονικά
αρχεία. Έτσι τα αρχεία στον δίσκο είναι πάντα πλήρη· μια κατάρρευση ή μια σκοτωμένη διεργασία χάνει το πολύ
τα τελευταία δευτερόλεπτα. Αν δεν κρατήθηκε τίποτα, τυπώνει πώς ανοίγει το Data Out και τερματίζει με κωδικό
εξόδου 1.

Έξοδος:

- `lap.npz` - πίνακες NumPy `positions` (n x 3, μέτρα), `times`, `speeds` (m/s)·
- `lap.json` - αναγνώσιμο χωρίς αυτό το έργο:

```json
{
  "layout": "Horizon dash",
  "samples": 4210,
  "seconds": 182.4,
  "metres_driven": 5120.7,
  "bounds": {"min": [-1200.0, 110.2, 300.5], "max": [-400.3, 160.8, 1400.0]},
  "positions": [[-1180.2, 112.0, 310.4], ...]
}
```

Οι θέσεις είναι οι συντεταγμένες του κόσμου του ίδιου του παιχνιδιού, και γι' αυτό είναι λαβή για να βρεθεί το
ίδιο έδαφος στα αρχεία του παιχνιδιού: η εντολή `course` του [3DHeat GameFiles](https://github.com/Holdi601/3DHeat-GameFiles)
παίρνει αυτό το JSON και εξάγει την πίστα πάνω από την οποία έτρεξε ο γύρος.

## laps {#laps}

```bash
python -m heat3d_capture laps                                   # list the courses
python -m heat3d_capture laps "a racing circuit" -o races/circuit [--library DIR] [--margin 80]
```

Διαβάζει τη βιβλιοθήκη γύρων που κρατά το FH Companion και γράφει δύο αρχεία για μία πίστα: μια διαδρομή που
δείχνει ποιο κομμάτι του χάρτη θα κοπεί από το αρχείο του παιχνιδιού, και έναν πίνακα με κάθε δείγμα κάθε
γύρου. Γράφονται μαζί, ώστε να μη μπορούν να βγουν εκτός συγχρονισμού. Κώδικας:
[`telemetry/fhcompanion.py`](https://github.com/Holdi601/3DHeat-GameCapture/blob/main/heat3d_capture/telemetry/fhcompanion.py).

| Επιλογή | Προεπιλογή | Σημασία |
|---|---|---|
| `course` | καμία | Όνομα πίστας, με χαλαρή αντιστοίχιση. Παραλείψτε το για να δείτε τη βιβλιοθήκη. |
| `-o`, `--out` | το όνομα της πίστας, με πεζά, τα κενά ως `_` | Διαδρομή εξόδου· γράφονται δίπλα-δίπλα τα `.json` και `.csv`. |
| `--library` | `%LOCALAPPDATA%\FHCompanion\laps` | Πού βρίσκονται οι φάκελοι των πιστών. |
| `--margin` | `80` | Μέτρα που προστίθενται γύρω από την έκταση της πίστας στα x και z, στα `bounds` της διαδρομής. |

### Λίστα {#listing}

Χωρίς πίστα, τυπώνει το πλήθος των φακέλων πίστας και, για καθέναν, το πλήθος των αρχείων γύρου (`*.json`
οπουδήποτε κάτω από αυτόν, εκτός από το `course.json`) και το όνομα της πίστας. Μετά τυπώνει τη γραμμή
`Name one to write it out:  -o <file> <course>`.

### Εύρεση πίστας {#finding-a-course}

Οι φάκελοι πίστας ονομάζονται `<name> (course_<x>_<z>_to_<x>_<z>)`: η αρχή και το τέλος, στρογγυλοποιημένα. Μια
πίστα βρίσκεται με αυτή τη σειρά: το ακριβές όνομα φακέλου· το μέρος ονόματος του φακέλου, χωρίς διάκριση
πεζών και κεφαλαίων· ένας μοναδικός φάκελος του οποίου το όνομα περιέχει το κείμενο. Αν ταιριάζουν περισσότεροι,
είναι σφάλμα, και η εντολή τους εμφανίζει όλους.

### Ανάγνωση {#reading-it}

- Το `course.json` μέσα στον φάκελο, όταν είναι αναγνώσιμο, δίνει το όνομα και την ακριβή αρχή και τέλος
  (`Name`, `StartX`, `StartZ`, `FinishX`, `FinishZ`)· αλλιώς αυτά προέρχονται από το όνομα του φακέλου. Μια
  πίστα θεωρείται κυκλική όταν η αρχή και το τέλος απέχουν λιγότερο από 10 m.
- Κάθε άλλο `*.json` κάτω από τον φάκελο είναι ένας γύρος. Οι γύροι βρίσκονται αρκετά επίπεδα βαθιά (ανά
  κατηγορία, αυτοκίνητο, ρύθμιση, ετικέτα), και η αναζήτηση είναι απλώς αναδρομική. Τα αρχεία διαβάζονται ως
  UTF-8 με BOM. Ένας γύρος που δεν διαβάζεται παραλείπεται. Οι γύροι ταξινομούνται κατά τον χρόνο καταγραφής.
- Ανά γύρο: `Lap.samples` (καθένα με `X`, `Y`, `Z`, `Speed`, `Throttle`, `Brake`, `Steer`, `LatG`, `LongG`,
  `Gear`, `Clutch`, `HandBrake`, `Puddle`, `Metres`, `Seconds`), και η κατηγορία του αυτοκινήτου, η σειρά του,
  ο δείκτης απόδοσης, τα δευτερόλεπτα του γύρου, το μήκος, ο χρόνος καταγραφής και η εκκίνηση από στάση.

Τυπώνει μια περίληψη (γύροι, δείγματα, ο καλύτερος γύρος και η κατηγορία του, η έκταση x/y/z).

### Έξοδος {#output}

**`<out>.json`**: το ίδιο σχήμα διαδρομής που γράφει το `route`, ώστε ο εξαγωγέας χαρτών να δέχεται το ένα ή το
άλλο: `layout: "fhcompanion"`, `course`, `laps`, `samples`, `bounds` (διευρυμένα κατά `--margin` στα x και z), και
`positions` του **ταχύτερου** γύρου (μία γραμμή αντί για θολούρα από όλους τους γύρους).

**`<out>.csv`**: κάθε δείγμα κάθε γύρου, μία γραμμή το καθένα:

| Στήλη | Σημασία |
|---|---|
| `course` | όνομα πίστας |
| `lap` | μία ετικέτα ανά γύρο: ημερομηνία και ώρα καταγραφής μέχρι το λεπτό, και ο χρόνος του γύρου |
| `car` | κωδικός αυτοκινήτου |
| `car_class` | γράμμα κατηγορίας απόδοσης |
| `pi` | δείκτης απόδοσης |
| `lap_seconds` | ο χρόνος του γύρου |
| `speed_kmh` | ταχύτητα σε km/h |
| `x`, `y`, `z` | θέση στον κόσμο, σε μέτρα, με 3 δεκαδικά |
| `speed_ms` | ταχύτητα, m/s |
| `throttle`, `brake`, `steer`, `lat_g`, `long_g`, `gear`, `clutch`, `handbrake`, `puddle` | όπως τα καταγράφει το FH Companion |
| `metres` | απόσταση κατά μήκος του γύρου, με 3 δεκαδικά |
| `elapsed` | δευτερόλεπτα από την αρχή του ίδιου του γύρου, με 3 δεκαδικά |

Οι τιμές που δεν είναι θέσεις γράφονται με 4 σημαντικά ψηφία. Οι θέσεις παίρνουν σταθερά δεκαδικά, γιατί τα 4
σημαντικά ψηφία θα έριχναν μια πίστα σε πλέγμα του ενός μέτρου. Τα ονόματα των στηλών επιλέχθηκαν ώστε ο
viewer να αντιστοιχίζει το αρχείο χωρίς να του το πει κανείς: το `lap` γίνεται η συνεδρία (δύο γύροι του ίδιου
αυτοκινήτου δεν ενώνονται ποτέ), το `car` το αντικείμενο που κινείται, το `car_class` η ομάδα για χρώμα, και το
`elapsed` ο άξονας του χρόνου (κάθε γύρος ευθυγραμμίζεται στη δική του αρχή).

Τέλος, τυπώνει μια υπόδειξη για το πώς κόβεται ο χάρτης από το παιχνίδι με το GameFiles, με το αρχείο διαδρομής
ή με ρητό πλαίσιο.

## reconstruct {#reconstruct}

```bash
python -m heat3d_capture reconstruct lap.mp4 -o lap.glb [--solve-budget 260] [--fuse-interval 0.4] [--model vggt-1b]
```

Ανασυνθέτει μια εγγραφή εκτός σύνδεσης, με τη διαδρομή της κάμερας να λύνεται όλη μαζί από το VGGT. Είναι αργή:
λεπτά ανά παράθυρο σε επιτραπέζια κάρτα γραφικών. Χρειάζεται PyTorch, Hugging Face `transformers` και το πακέτο
`vggt`, που ο σαρωτής δεν χρειάζεται: βρίσκονται στο `requirements-offline.txt`, και η εντολή τα ελέγχει αφού
τυπώσει τη γραμμή άδειας. Τότε προσφέρεται να εγκαταστήσει ό,τι λείπει (κωδικός εξόδου 1 αν αρνηθείτε). Πλήρης
περιγραφή: [Ανασύνθεση εκτός σύνδεσης](reconstruction-offline.md).

| Επιλογή | Προεπιλογή | Σημασία |
|---|---|---|
| `video` | απαιτείται | Η εγγραφή. Κωδικός εξόδου 2 αν δεν υπάρχει. |
| `-o`, `--out` | απαιτείται | Το `.glb` που θα γραφτεί. |
| `--solve-budget` | `260` | Τα περισσότερα καρέ που δίνονται στον επιλυτή. Απλώνονται ανάλογα με το πόσο κινείται η εικόνα, όχι με το ρολόι. Περισσότερα σημαίνει μεγαλύτερη ακρίβεια και πολύ μεγαλύτερο χρόνο. Πάνω από 400 προγραμματισμένα καρέ απορρίπτονται. |
| `--fuse-interval` | `0.4` | Δευτερόλεπτα ανάμεσα στα καρέ που ενώνονται σε γεωμετρία. |
| `--model` | `vggt-1b` | Ποια βάρη VGGT χρησιμοποιούνται για την επίλυση: `vggt-1b` (`facebook/VGGT-1B`, μη εμπορικό) ή `vggt-1b-commercial` (`facebook/VGGT-1B-Commercial`, με έλεγχο πρόσβασης· χρειάζεται πρόσβαση που δίνει η Meta). Η γραμμή άδειας που τυπώνεται πρώτη είναι του μοντέλου που επιλέξατε. |

Τυπώνει πρώτα τη γραμμή άδειας του μοντέλου, μετά κάθε στάδιο (`masking`, `planning`, `solving`, `fusing`,
`exporting`) με τα δευτερόλεπτα που πέρασαν και την πρόοδο, και τέλος μια περίληψη: κάμερες που λύθηκαν, σφάλμα
κλεισίματος, χειρότερη ραφή, σημειώσεις και το αρχείο που γράφτηκε. Ο κωδικός εξόδου είναι 0 μόνο αν γράφτηκε
αρχείο.

## hud {#hud}

```bash
python -m heat3d_capture hud "<recording>.mp4" --game bf6 --player <name> -o out/match [--fps 5] [--start S] [--seconds S] [--metres-per-pixel M] [--cpu]
```

Διαβάζει το HUD του παιχνιδιού από τη **δική του** εγγραφή του παίκτη, μετά τον αγώνα: τις δικές του ενέργειες από
το αναδυόμενο παράθυρο πόντων, τους θανάτους και τις αναβιώσεις από τις οθόνες πτώσης και ανάπτυξης, τη διαδρομή
του στον χάρτη και τη ροή των φόνων. Γράφει `<out>.parquet` (διαδρομή και συμβάντα, ένας πίνακας 3DHeat),
`<out>.events.jsonl`, `<out>.summary.json`, και `<out>.map.png` + `.map.json` (το μωσαϊκό του χάρτη και τα σημεία
αγκύρωσής του, για την Εικόνα χάρτη του viewer). Το Battlefield 6 (`bf6`) είναι μέχρι τώρα το μόνο προφίλ.

Χρειάζονται **ffmpeg και ffprobe** στο PATH (`winget install Gyan.FFmpeg`, και μετά ένα νέο τερματικό).

| Επιλογή | Προεπιλογή | Σημασία |
|---|---|---|
| `video` | απαιτείται | Η εγγραφή. |
| `-o`, `--out` | το όνομα του βίντεο | Διαδρομή εξόδου χωρίς επέκταση. |
| `--game` | `bf6` | Ποιο HUD διαβάζεται. |
| `--player` | εκτιμάται | Το όνομα του παίκτη όπως το δείχνει η ροή φόνων, με χαλαρή αντιστοίχιση. |
| `--fps` | `5` | Δείγματα χάρτη ανά δευτερόλεπτο. |
| `--start`, `--seconds` | ολόκληρο το βίντεο | Το μέρος της εγγραφής που διαβάζεται. |
| `--metres-per-pixel` | καμία | Η κλίμακα του χάρτη, όταν είναι γνωστή· χωρίς αυτήν, οι θέσεις είναι σε pixel του χάρτη. |
| `--cpu` | απενεργοποιημένο | Αποκωδικοποίηση στον επεξεργαστή, ακόμη κι αν υπάρχει κάρτα NVIDIA. |

Πλήρης περιγραφή: [Ανάγνωση του HUD από εγγραφή](hud-video.md).

## locate {#locate}

```bash
python -m heat3d_capture locate build level.glb -o level.db [--game bf6] [--spacing 2.5] [--shadows]
python -m heat3d_capture locate frames recording.mp4 --db level.db -o out/match [--fps 2] [--minimap match.parquet]
python -m heat3d_capture locate eval out/match.parquet --truth poses.parquet [--offset S] [--unit-metres 1]
python -m heat3d_capture locate train level.glb -o level.head.pt [--places auto] [--real out/match.parquet recording.mp4]
python -m heat3d_capture locate refmap level.glb deploy.png -o out/refmap [--mpp 0.5]
python -m heat3d_capture locate minimap recording.mp4 --refmap out/refmap -o out/minimap.parquet [--hud out/match.parquet]
```

Το `build` αποδίδει μια πίστα από κάθε θέση όπου μπορεί να σταθεί ένας παίκτης, και δεικτοδοτεί τις αποδόσεις.
Το `frames` τοποθετεί κάθε δειγματοληπτούμενο καρέ μιας εγγραφής απέναντί τους, από την εικόνα, με τη διαδρομή
του χάρτη της εντολής `hud` ως εναλλακτική. Το `eval` συγκρίνει ένα αποτέλεσμα με γνωστές θέσεις κάμερας. Το
`train` εκπαιδεύει ένα μοντέλο θέσεων για κάθε χάρτη, σε αποδόσεις της πίστας (και σε καρέ που μια εκτέλεση έχει
ήδη τοποθετήσει), για το `build --head`. Το `refmap` τοποθετεί τον ίδιο τον χάρτη του παιχνιδιού (την οθόνη
ανάπτυξης) πάνω στην πίστα, και το `minimap` διαβάζει τον χάρτη μιας εγγραφής απέναντί του, καρέ προς καρέ. Το
προηγούμενο `frames --minimap` μπορεί να το δεχθεί ως αρχική εκτίμηση. Χρειάζονται PyTorch και το
`requirements-locate.txt`. **Πειραματικό:** σε πραγματικές εγγραφές τοποθετεί μέχρι στιγμής μόνο ένα μικρό μέρος
των καρέ. Κάθε επιλογή, τα αποτελέσματα και η μέθοδος: [Εντοπισμός καρέ σε πίστα](locate.md)· η πλήρης λίστα
επιλογών: [Αναφορά εντολών](../cli-reference.md).

## Μετατροπέας μοντέλου {#the-model-converter}

```bash
python tools/export_onnx.py [--size small|base|large] [--out PATH] [--side 518] [--opset 17]
```

Μετατρέπει ένα σημείο ελέγχου Depth Anything V2 στο αρχείο ONNX που εκτελεί ο σαρωτής. Χρειάζονται PyTorch,
`transformers` και `onnxscript`. Βλ. [Βάθος](reconstruction-depth.md#building-the-model).
