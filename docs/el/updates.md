# Ενημερώσεις {#updates}

Το 3DHeat GameCapture ελέγχει τις εκδόσεις (releases) αυτού του αποθετηρίου στο GitHub όταν ξεκινά, λέει
πότε υπάρχει νεότερη έκδοση, και προσφέρεται να ενημερωθεί. Κώδικας:
[`heat3d_update/`](https://github.com/Holdi601/3DHeat-GameCapture/tree/main/heat3d_update).

## Πότε γίνεται ο έλεγχος {#when-the-check-runs}

- `python -m heat3d_capture <verb>` - πριν τρέξει η εντολή.
- `python -m heat3d_capture.ui` (και το `scan.bat`) - πριν ανοίξει το παράθυρο.
- `python -m heat3d_update` - όταν το ζητήσετε, ρωτώντας πάντα το GitHub από την αρχή.

## Πώς γίνεται ο έλεγχος {#how-the-check-works}

- Η εγκατεστημένη έκδοση είναι το αρχείο `VERSION` στη ρίζα του αποθετηρίου (για παράδειγμα `1.0.1`).
- Η νεότερη έκδοση ζητείται από το `https://api.github.com/repos/Holdi601/3DHeat-GameCapture/releases/latest`,
  με χρονικό όριο **5 δευτερολέπτων**. Ένα αργό δίκτυο δεν κρατά το εργαλείο περισσότερο από αυτό.
- Η απάντηση αποθηκεύεται για **6 ώρες** στο
  `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-GameCapture.json` (`~/.cache/3DHeat/...` χωρίς το
  `LOCALAPPDATA`). Κάθε εργαλείο 3DHeat έχει το δικό του αρχείο προσωρινής μνήμης. Το «δεν υπάρχει έκδοση
  ακόμη» (HTTP 404) αποθηκεύεται όπως μια απάντηση· οι άλλες αποτυχίες δεν αποθηκεύονται και απλώς
  σημαίνουν ότι δεν εμφανίζεται ειδοποίηση.
- Οι εκδόσεις συγκρίνονται αριθμητικά (`v1.2.3` ή `1.2.3`· ό,τι βρίσκεται μετά το `-` ή το `+` αγνοείται).
- Χωρίς σύνδεση, σε περιορισμό ρυθμού ή πίσω από διακομιστή μεσολάβησης, το εργαλείο συνεχίζει με την
  έκδοση που έχει.

## Τι γίνεται όταν υπάρχει νεότερη έκδοση {#what-happens-when-a-newer-release-is-out}

Κατά την εκκίνηση τυπώνει, στη ροή σφαλμάτων:

```text
[heat3d_capture] 3DHeat GameCapture 1.1.0 is out (this is 1.0.1). https://github.com/...
```

- Αν υπάρχει τερματικό για να απαντήσετε, ρωτά `Update now? [Y/n]` (Enter, `y`, `yes`, `j`, `ja` σημαίνουν
  ναι). Μετά από επιτυχημένη ενημέρωση **η ίδια εντολή ξαναρχίζει**, με τον νέο κώδικα.
- Αν δεν υπάρχει (σωλήνωση, προγραμματισμένη εκτέλεση), τυπώνει
  `Run python -m heat3d_update in <folder> to update.` και συνεχίζει αμετάβλητο.

## Πώς εφαρμόζεται μια ενημέρωση {#how-an-update-is-applied}

Εξαρτάται από τον τρόπο εγκατάστασης των εργαλείων:

- **Κλώνος git** (φάκελος `.git` και το `git` στο PATH): `git pull --ff-only`. Αρνείται όσο το checkout έχει
  τοπικές αλλαγές σε αρχεία υπό παρακολούθηση - αυτή είναι δουλειά κάποιου· υποβάλετε ή αποθηκεύστε τις
  πρώτα.
- **Αντίγραφο που κατέβηκε**: το αρχείο πηγαίου κώδικα της έκδοσης κατεβαίνει, αποσυμπιέζεται σε
  προσωρινό φάκελο (καταχωρίσεις έξω από τον δικό του φάκελο του αρχείου παραλείπονται), και
  **ελέγχεται ότι είναι η έκδοση που δηλώνει** από το αρχείο `VERSION` του. Μετά τα αρχεία του
  αντιγράφονται πάνω σε αυτόν τον φάκελο. Μέσα στα δικά της πακέτα Python της έκδοσης (φάκελοι `heat3d_*`
  στην κορυφή του αποθετηρίου, και ένα επίπεδο πιο κάτω για την παλιά δομή μονοαποθετηρίου), τα αρχεία
  `.py` που δεν υπάρχουν πια στην έκδοση διαγράφονται, ώστε μια ξεπερασμένη μονάδα να μην σκιάζει την
  αντικαταστάτριά της.

Τα δικά σας αρχεία - εγγραφές, αρχεία γύρων, ρυθμίσεις, εξαγωγές, το `.venv` - δεν αγγίζονται ποτέ: γράφονται
μόνο τα αρχεία που ανήκουν στην έκδοση.

## Με το χέρι {#by-hand}

```bash
python -m heat3d_update            # έλεγχος και ενημέρωση
python -m heat3d_update --check    # μόνο να πει αν υπάρχει νεότερη έκδοση
```

Τυπώνει `Up to date: <version>.`, `No release found ... offline, or nothing published yet.`, ή τη νέα
έκδοση και τι έκανε. Κωδικός εξόδου 1 αν η ενημέρωση δεν μπόρεσε να εφαρμοστεί.

## Απενεργοποίηση {#switching-it-off}

Ορίστε το **`HEAT3D_NO_UPDATE=1`** (οποιαδήποτε τιμή εκτός από κενό, `0`, `false`, `no`). Αυτό απενεργοποιεί
τον έλεγχο και την ειδοποίηση κατά την εκκίνηση. Το `python -m heat3d_update` εξακολουθεί να ελέγχει όταν
εκτελείται με το χέρι.
