# Обновления {#updates}

3DHeat GameCapture проверява GitHub изданията на това хранилище при стартиране, казва кога е излязла по-нова версия и предлага обновяване. Код: [`heat3d_update/`](https://github.com/Holdi601/3DHeat-GameCapture/tree/main/heat3d_update).

## Кога става проверката {#when-the-check-runs}

- `python -m heat3d_capture <verb>` - преди командата да се изпълни.
- `python -m heat3d_capture.ui` (и `scan.bat`) - преди да се отвори прозорецът.
- `python -m heat3d_update` - при поискване, като винаги пита GitHub наново.

## Как работи проверката {#how-the-check-works}

- Инсталираната версия е файлът `VERSION` в коренната папка на хранилището (например `1.0.1`).
- Най-новото издание се пита от `https://api.github.com/repos/Holdi601/3DHeat-GameCapture/releases/latest`, със **5-секунден** таймаут. Бавна мрежа никога не спира инструмента за по-дълго.
- Отговорът се кешира за **6 часа** в `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-GameCapture.json` (`~/.cache/3DHeat/...` без `LOCALAPPDATA`). Всеки инструмент на 3DHeat има собствен кеш файл. „Още няма издание“ (HTTP 404) се кешира като отговор; други грешки не се кешират и означават просто, че няма известие.
- Версиите се сравняват числено (`v1.2.3` или `1.2.3`; всичко след `-` или `+` се пренебрегва).
- Офлайн, при ограничение на заявките или зад прокси, инструментът продължава с версията, която има.

## Какво става, когато има по-ново издание {#what-happens-when-a-newer-release-is-out}

При стартиране извежда в потока за грешки:

```text
[heat3d_capture] 3DHeat GameCapture 1.1.0 is out (this is 1.0.1). https://github.com/...
```

- Когато има терминал за отговор, пита `Update now? [Y/n]` (Enter, `y`, `yes`, `j`, `ja` означават да). След успешно обновяване **същата команда се стартира отново**, с новия код.
- Без терминал (тръба, планирано пускане) извежда `Run python -m heat3d_update in <folder> to update.` и продължава непроменено.

## Как се прилага обновяването {#how-an-update-is-applied}

Зависи как са инсталирани инструментите:

- **Клониране с git** (папка `.git` и `git` в PATH): `git pull --ff-only`. Отказва, докато в копието има локални промени по проследявани файлове - те са нечия работа; първо ги подайте (commit) или ги сложете в скрито хранилище (stash).
- **Свалено копие**: архивът с изходния код на изданието се сваля, разархивира във временна папка (записите извън собствената папка на архива се пропускат) и се **проверява, че е версията, която твърди**, по файла му `VERSION`. После файловете му се копират върху тази папка. В собствените Python пакети на изданието (папките `heat3d_*` в горната част на хранилището, а едно ниво по-надолу - при стария общ формат), `.py` модулите, които изданието вече няма, се изтриват, за да не засенчи остарял модул новия му заместник.

Вашите собствени файлове - записи, файлове с обиколки, настройки, експорти, `.venv` - никога не се пипат: записват се само файлове, които са част от изданието.

## Ръчно {#by-hand}

```bash
python -m heat3d_update            # check and update
python -m heat3d_update --check    # only say whether a newer release is out
```

Извежда `Up to date: <version>.`, `No release found ... offline, or nothing published yet.` или новата версия и какво е направил. Код на изход 1, ако обновяването не може да се приложи.

## Изключване {#switching-it-off}

Задайте **`HEAT3D_NO_UPDATE=1`** (всяка стойност, освен празна, `0`, `false`, `no`). Това изключва проверката и известието при стартиране. `python -m heat3d_update` сам по себе си пак проверява, когато се пуска ръчно.
